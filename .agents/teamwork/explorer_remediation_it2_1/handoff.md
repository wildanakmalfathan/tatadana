### Observation 2: Defect 2 — Case-Sensitivity Risk in Windows Batch Loop Assertion (Line 670)
- **File**: `tests/e2e/tier1-features.test.mjs` (lines 664–671):
  ```javascript
  664:   it('verifies Windows batch launcher scripts/start-telegram-bot.bat provides auto-restart loop', () => {

  666:     expect(fileExists(batchPath)).toBeTruthy();
  667:     const content = readFileSafe(batchPath);
  668:     expect(content).toContain(':LOOP');
  669:     expect(content).toContain('telegram-daemon.mjs');
  670:     expect(content).toContain('GOTO LOOP');
  671:   });
  ```
- **Target File**: `scripts/start-telegram-bot.bat`:
  - Line 28: `:LOOP`
  - Line 38: `GOTO LOOP`
- **Auditor & Reviewer Finding**:
  In Windows cmd/batch scripting, commands are case-insensitive (`goto LOOP`, `GOTO LOOP`, `Goto Loop` are all syntactically identical). However, `expect(content).toContain('GOTO LOOP')` uses JavaScript's `String.prototype.includes` which is strictly case-sensitive. If the batch script is formatted with lowercase `goto LOOP`, this test throws:
  `Error: Expected string to contain "GOTO LOOP"`.
  Reviewer 1 specifically recommended changing line 670 to `expect(content.toUpperCase()).toContain('GOTO LOOP')`.
